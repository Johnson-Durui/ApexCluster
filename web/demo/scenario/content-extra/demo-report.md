# 核心路径 Demo 运行报告

执行者：Sol · 架构阶段（关卡 A 之前）

目的：在冻结需求契约之前，用一个最小原型实际跑通“预约 → 冲突检测 → 建议时段 → iCal 导出”这条核心路径，确认技术架构里的三条关键规则可行。原型放在 `.agent/demo/`，不进入交付代码；正式实现见里程碑 M-API 与 M-UI。

## 运行

```
$ node .agent/demo/core-path-demo.mjs
会议室：3 层 8 间
预约 1：银杏 09:30–10:30 产品评审 → 已保存
预约 2：枫林 13:00–14:00 接口联调：预约服务与日历导出的端到端验证（中文长标题折行检查） → 已保存
预约 3：银杏 10:00–11:00 周会 → 冲突（与「产品评审」09:30–10:30 重叠）
建议时段：银杏 10:30–11:30
iCal：1 个 VCALENDAR，2 个 VEVENT，行尾全部 CRLF，最长物理行 74 字节
折行展开后与原文一致：是
```

退出码 0。

## 结论

| 规则 | 结果 |
|---|---|
| 冲突按半开区间 [开始, 结束) 判断 | 成立：10:00–11:00 与 09:30–10:30 重叠被拒绝；建议的 10:30–11:30 与 09:30–10:30 首尾相接，不算冲突 |
| 建议时段：同一会议室、时长不变、离原开始时间最近，同距离优先顺延 | 成立：返回 10:30–11:30 |
| iCal：转义、75 字节折行、CRLF | 成立：31 个汉字的主题按字节折行，最长物理行 74 字节，展开后与原文一致，没有单独的 LF |

原型用到的数据和规则与 PRD 第 4 节一致，可以冻结需求契约。
