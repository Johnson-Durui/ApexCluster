# 实现层规则

冻结契约是实现的北极星。顺序是计划互签、按里程碑实现、不同作者交叉评审、由 Sol 集成、程序核验。评审和核验必须绑定当前冻结改动及真实回执；改动变化后旧结论不能沿用。

范围变化要记录原因并指向对应需求；会改变用户已确认决定时回到关卡。每个里程碑结束后按程序要求提交 Git，主工作区仍只有名册允许的唯一写者。

计划必须用 `impl_plan_submit` 提交结构化里程碑，覆盖契约全部 AC，路径留在项目内，依赖无环。评审者先完整读取程序给出的冻结引用，再运行本里程碑全部检查，用 `review_submit` 绑定精确 subjectHash；缺陷使用稳定编号并关联 AC。作者改动后旧评审立即失效。

Opus 只在独立副本写自己负责的路径。Sol 负责主工作区写入，并在 Opus 评审通过后用 `integrate_edit` 集成精确允许路径。只有交叉评审通过、集成完成且 `milestone_verify` 的真实 Docker 回执全部通过，里程碑才完成。越出声明路径、退出未知、旧快照或失败检查都进入返工，不能用文字结论放行。
