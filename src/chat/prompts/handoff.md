# 换段与交接规则

逻辑任务可以跨多个模型调用段继续；换段只结束当前 Invocation，不代表任务、子任务或聊天完成。达到 12 次工具动作、15 分钟主动运行、已验证窗口 50%、主动 `task_yield` 或等待边界时，用最短可执行说明交接，然后立即停止当前段。

程序检查点才是恢复依据，至少保存任务和子任务状态、用户约束消息来源、待处理票据、产物、下一步及时间；文件哈希和测试证据由程序记录。模型交接说明只补充以下内容：

- 本段实际完成了什么，以及对应工具回执、文件/结果引用；
- 哪些结论仍未验证，不能在下一段当作事实；
- 下一段的一个明确动作和停止条件；
- 已发现的权限、并发修改、进程退出或测试风险。

若必保用户原文采用来源分页，程序状态中的来源 ID、SHA-256 和已提供 offset 是权威覆盖记录。交接说明只写下一项需要读取的来源/offset；新段先用 `task_state` 或来源索引复核，再把 `user_source_read` 返回的 `next` 原样作为后续 offset。哈希变化表示原文已更新，旧覆盖不可沿用。程序记录“已提供”不等于模型已经理解，下一段仍需按完整原文核对结论。

不要复制长日志、整份子任务结果或全部聊天记录到交接说明；保留引用并在下一段按需读取。不要用摘要改写用户原文，用户约束以原消息 ID 和完整消息存储为准。真实上下文窗口或占用未知时写 `null`/“未知”，不猜百分比，不把历史累计 token 当作新段占用。

等待用户、子任务或测试时，先由工具创建持久票据；一旦收到 `wait` 就结束本段。新段应重新读取程序事实和最新用户要求，不能依赖模型进程仍在，也不能自动重放退出状态未知、取消或中断的执行。12 次工具动作导致的换段不会抹掉来源覆盖；已经读取的新页面计入真实进展，应在后续段继续完成全部来源，而不是跳页或提前完成。
